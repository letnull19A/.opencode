# Название

Словесное описание навыков пакета.

# Назначение

Перечислить все навыки пакета и их роль как дисциплины использования скриптов, чтобы исполнитель знал, какой навык загрузить перед действием.

# Входы

- Заголовки описаний из файлов навыков
- Связи навыков со скриптами и агентами

# Выходы

- Перечень навыков с ролью каждого словами
- Понимание, какой навык за какую операцию отвечает

# Зависимости

- Скрипты, которые навыки описывают
- Агенты, которые навыки применяют

# Ограничения

- Только слова, без программных блоков
- Без секретных значений
- Навыки описывают порядок, сами мутации делают скрипты

# Когда использовать

- Когда нужно узнать правильную дисциплину перед операцией
- Когда нужно выбрать навык для планирования, веток, проверок, доставки

# Перечень навыков словами

Работа с ветками: опасные веточные операции только через изолированную копию с проверкой изоляции и движением только вперед.

Проверки изменений: проверка только незафиксированных изменений через единый скрипт вместо ручных вызовов типов и линтеров.

Непрерывная интеграция: построение конвейеров сборки и публикации образов без привязки к поставщику с опросом требований и детерминированным скаффолдом.

Коммиты: стратегия атомарных conventional-сообщений с группировкой по смыслам.

Дизайн интерфейса: применение руководства по стилю через программный контекст и предкоммитную проверку.

Окружение стенда: конвенция разделов запуска в главном описании проекта.

Диагностика: пошаговое следствие от разведки к виновнику сбоя.

Упаковка образов: послойная упаковка с кэшированием зависимостей и изучением стека.

Планирование под задачи: составление плана, сразу готового к записи в карточки.

Дисциплина истории: линейная история без слияний, только синхронизация через перебазирование.

Разведка истории: только чтение состояния репозитория одиночными разрешенными командами.

Индексация и поиск: быстрый поиск по именам файлов и содержимому через скрипт индекса вместо ручных средств.

Дисциплина хостинга: кто что исполняет при работе в ограниченном окружении, где разрешения не действуют.

Инициализация профиля: опрос характеристик проекта и запись профиля с детальностью комментариев.

Разработка модуля: жизненный цикл модуля через стратегии добавления и изменения с делегированием тестов и реализации.

Вложенность: карта вложенности как графа для порядка карточек по связям блокировок.

Планировщик батчей: группировка легких задач и проверка наличия инструкции исправления.

Запросы слияния: единственный источник правды по запросам через скрипты, прямые вызовы запрещены.

Отправка: отправка только зафиксированных коммитов без добавления и форсирования.

Исправление интерфейса: поиск класса скриптом, вопрос пользователю, затем точечная правка.

Маршрутизация доступа: классификация единиц на открытые и требующие входа до планирования.

Запуск скриптов: только запуск скрипта и передача вывода без правок кода.

Безопасность: проверка staged-ввода перед каждым коммитом с остановкой при опасных приемниках.

Синхронизация: подтягивание удаленной ветки только через перебазирование с автосохранением.

Управление задачами: качественное ведение карточек через скрипты без прямых вызовов интерфейса.

Предпросмотр: управление внешним доступом к запущенному серверу.

Управление параллельными копиями: создание, список, статус и удаление изолированных копий.
