# Название

Словесное описание агентов пакета по отделам.

# Назначение

Перечислить всех агентов пакета, их роль и принадлежность к отделу конвейера, чтобы по описанию можно было выбрать нужного исполнителя без чтения исходных файлов.

# Входы

- Заголовки описаний из файлов агентов
- Деление на отделы: разведка, планирование, задачи, исполнение, проверка, доставка, сквозные
- Правила вызова: точка входа и скрытые подагенты

# Выходы

- Группированный перечень агентов с ролью каждого словами
- Понимание, кто думает, кто исполняет, кто проверяет
- Понимание, кого нельзя вызывать напрямую

# Зависимости

- Навыки, описывающие дисциплину каждого агента
- Скрипты, которые агенты запускают
- Рабочие процессы, которые агентов оркестрируют

# Ограничения

- Только слова, без программных блоков
- Без секретных значений
- Описания не меняют поведение агентов

# Когда использовать

- Когда нужно выбрать исполнителя для задачи
- Когда нужно понять, скрытый агент или прямой
- Когда нужно объяснить структуру команды новичкам

# Перечень по отделам словами

Разведка: главный агент вопросов и ответов только читает и объясняет без изменений; агент разведки собирает сведения из документов и файлов для точного плана; агент нормализации превращает сырой ввод в структурированное описание с оценкой; агент ручного режима передает управление пользователю без автоматической маршрутизации.

Планирование: главный маршрутизатор оценивает запрос, классифицирует и делегирует, сам код не пишет; улучшенный планировщик выступает оркестратором планирования; скрытый планировщик разбивает задачу на карточки с чек-листами и связями блокировок.

Задачи: ответственный за задачи ведет карточки проектного тега, батчи и аудит; аудитор возвращает строго структурированный итог проверки доски; группировщик объединяет легкие задачи в совместные батчи; объясняющий раскрывает смысл задачи словами; сборщик проблем выдает строго проверенный структурированный объект проблемы; оркестратор инициализации опрашивает пользователя для профиля проекта; исполнитель инициализации записывает профиль через скрипт.

Исполнение: быстрый исполнитель для простых задач по готовому плану; умный исполнитель для сложных и связанных с зависимостями задач с глубокой проверкой; исполнитель по умолчанию для случаев, когда сложность не определена; универсальный рефакторинг с предварительным изучением соглашений проекта; исполнитель тестов под любой язык с уточнением синтаксиса из актуальной документации; проектировщик компонентов только для чтения и скрытый; оркестратор интерфейса ведет двухэтапный конвейер; точечный исправитель интерфейса ищет класс скриптом и правит только подтвержденное; упаковщик образов собирает послойную упаковку с изучением стека; оркестратор непрерывной интеграции скаффолдит конвейеры без привязки к поставщику; исполнитель конвейеров выполняет готовые требования без опроса; исполнитель инфраструктуры ведет сети окружения и развертывание и вызывается только через классификатор.

Проверка: диагност расследует сбои от разведки к виновнику; отчет по снимкам делает визуальную проверку по нескольким размерам экрана; гейт качества сверяет изменения с правилами по фиксированным критериям и код не правит; разрешающий конфликты предлагает точечное разрешение только после подтверждения и сам слияние не продолжает.

Доставка: автор коммитов разбивает изменения на атомарные conventional-сообщения без отправки; управляющий параллельными рабочими копиями ведет их жизненный цикл; управляющий предпросмотром открывает внешний доступ к запущенному серверу.

Сквозные: аудитор безопасности разбирает нарушения контрольной проверки и предлагает правки проверок; владелец архитектурного описания ведет единственный архитектурный файл и код не трогает.

Уточнение интерфейсной четверки словами: проектировщик компонентов скрытый и только читает, выдает дерево и ответственности и контракты свойств и разбиение крупного на мелкие, вызывается только через план или делегирование; оркестратор интерфейса скрытый и только делегирует скрытым концепту и реализации; концепт скрытый и выдает абстрактную разметку по слоям без конкретики; реализация скрытая и отображает абстрактный слой в конкретные компоненты и файлы с потоком данных.

Уточнение таблицы отделов словами на тридцать семь: ручной маршрутизатор с режимом все вне отделов как ручное управление без автоматики; дефолтный исполнитель в исполнении как страховка при неопределенной сложности; разрешающий конфликты в проверке как точечное разрешение после утверждения.
