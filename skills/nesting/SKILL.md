Ты строишь карту вложенности как ориентированный граф поверх карточек Trello.
Графа в самом Trello нет — рёбра берутся из строки `Blocked by:` в `## Связи`
(парсинг — `scripts/task-manager/audit.sh` / `dump.sh` → `blocked_by[]`).

## Узел и ребро (формат зафиксирован)

- **Узел** — карточка-модуль: `{shortUrl, title, unit, layer}`,
  где `unit` — единица классификации (`страница|модуль` фронт,
  `эндпоинт|модуль` бэк — `skills/routing/SKILL.md`), `layer` — слой
  фактора 3 (`skills/evol-plan/SKILL.md#2b`).
- **Ребро** `A —Blocked by→ B` — в `## Связи` карточки A есть строка
  `Blocked by: <shortUrl B>` (несколько URL через запятую = несколько рёбер).
  Смысл: A ждёт B, порядок — сначала B, потом A.
- **Степени:** `in(X) = |blocked_by[X]|` (сколько блокируют X);
  `out(X) = |{Y : X ∈ blocked_by[Y]}|` (сколько X блокирует, считается
  по всему множеству карточек из `dump.sh`/`audit.sh`, не по одной карточке).

## Правила root/branch/leaf (закрытые, других трактовок нет)

| Тип | Условие | Порядок |
| --- | --- | --- |
| `root` | `in = 0` — никем не заблокирована. Подвиды: `isolated` (`out = 0`, порядок любой) / `source` (`out > 0`, первой) | первой (или любой при `isolated`) |
| `branch` | `in > 0` и `out > 0` — и заблокирована, и блокирует | посередине |
| `leaf` | `in > 0`, `out = 0` — только заблокирована | последней |
| `unknown` | fallback — графа нет (см. ниже) | без `Blocked by`-порядка, снять `audit.sh` |

## unknown-fallback (не гадать root)

`unknown` ставится когда: вход `{nesting, blocked_by[]}` не снят
(`dump.sh`/`audit.sh` не прогонялись); `blocked_by` ссылается на URL вне
известного множества карточек; ссылка битая. Нет данных — `unknown`,
а не `root`; план при этом — без порядка по вложенности + пометка
«снять граф». В однозадачном входе `workflows/new-task` степени берутся
из `{blocked_by, blocks_others}` (`steps/04-plan.ts`): `[] + blocks_others`
→ `root`, `non-empty + blocks_others` → `branch`, `non-empty` → `leaf`,
иначе `unknown`.

## Запреты

- Циклы запрещены (`A Blocked by B` + `B Blocked by A`) — вернуть план
  на доработку, разорвать одно ребро.
- Рёбра — только из точных URL `dump.sh`/`audit.sh`, никогда из головы.
- Не вводить 5-й фактор матрицы и 5-й тип вложенности без отдельной карточки
  (правило как в `skills/routing/SKILL.md` и `skills/evol-plan/SKILL.md#2b`).
- Не смешивать граф с чек-листами: граф — порядок карточек,
  чек-лист — пункты внутри одной карточки.

## Вход в матрицу (фактор 4)

Этот файл — источник фактора 4 (`skills/evol-plan/SKILL.md#2b`):
значения `root|branch|leaf|unknown` + `blocked_by URLs`.
Компиляция — `workflows/new-task/steps/04-plan.ts` (строка `Вложенность: …`
в `## Контекст` каждой карточки + порядок через `Blocked by:`).
Валидация complex-плана: строка вложенности есть + порядок
`root → branch → leaf` соблюдён; нет одного — план неполон.

## Примеры: таблица + матрица (прогон через `025-route-classify.ts` + `04-plan.ts`)

1. **Public страница** — «Добавить страницу лендинга» / «Публичная страница
   каталога помощи, доступна всем без ограничений»:
   таблица → два вопроса (login не нужен, не мешает) → `public`
   (`страница`, `front`); матрица → `route:public, role:user, layer:pages`,
   `nesting:root` (граф снят: `in=0` → `root`; при `out=0` — подвид `isolated`,
   порядок любой); критериев доступа нет (только `auth/unauth` их добавляют).
2. **Auth эндпоинт** — «Добавить эндпоинт POST /api/orders» / «Только для
   авторизованных пользователей, гость получает 401» + `Blocked by: <auth-guard>`:
   таблица → нужен login → `auth` (`эндпоинт`, `back`); матрица →
   `route:auth, role:guest, layer:service`, `nesting:leaf` (`in=1, out=0` —
   делать после блокера); при `complex=true` в критерии добавляется
   «Гость → редирект на вход / 401–403 (таблица routing)».
3. **Unauth страница** — «Добавить экран входа» / «Экран входа только для
   гостя, пользователь перенаправляется в приложение» +
   `Blocked by: <дизайн>` + блокирует дашборд (`blocks_others`):
   таблица → login мешает → `unauth` (`страница`, `front`); матрица →
   `route:unauth, role:user, layer:pages`, `nesting:branch` (`in>0, out>0` —
   посередине); при `complex=true` в критерии добавляется
   «Пользователь → редирект в приложение / 403 (таблица routing)».

## Что не делать

- Не строить граф здесь вместо `dump.sh`/`audit.sh` — этот файл правило,
  данные всегда из скриптов.
- Не ставить тип целому сервису — только узел-модуль
  (`страница|модуль` / `эндпоинт|модуль`).
- Не дублировать факторы 1–3 — они в `skills/routing/SKILL.md`
  и `skills/evol-plan/SKILL.md#2b`.
