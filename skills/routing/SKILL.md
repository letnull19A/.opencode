Ты классифицируешь любой роут одним из 3 типов. Трактовка одинакова
для фронта и бэка — различается только единица классификации.

## Единица классификации

- Фронт — **страница|модуль** (страница целиком либо модуль внутри неё).
- Бэк — **эндпоинт|модуль** (эндпоинт целиком либо модуль/хендлер внутри него).

Правило роутинга едино для фронтендеров и бэкендеров: тип ставится
на единицу (страница|модуль спереди, эндпоинт|модуль сзади), а не на
«экран» или «сервис» в целом.

## 3 типа (определения зафиксированы)

- **public** — доступен всем без ограничений. Не требует аутентификации
  и не запрещён аутентифицированным. Пример фронта: лендинг, страница
  помощи. Пример бэка: health-check, публичный каталог.
- **auth** — только аутентифицированным. Анонимный доступ запрещён;
  неаутентифицированного — редирект на вход (фронт) / `401/403` (бэк).
  Пример фронта: дашборд, настройки профиля. Пример бэка: `POST /api/orders`,
  `GET /api/me`.
- **unauth** — только неаутентифицированным. Аутентифицированным доступ
  закрыт; аутентифицированного — редирект в приложение (фронт) /
  `403` или редирект (бэк). Пример фронта: страница входа, регистрация,
  восстановление пароля. Пример бэка: `POST /api/auth/login`,
  `POST /api/auth/register`.

## Как ставить тип

1. Определи единицу: фронт — страница|модуль, бэк — эндпоинт|модуль.
2. Ответь на два вопроса: «нужен ли login?» и «мешает ли login?».
   - Не нужен и не мешает → **public**.
   - Нужен → **auth**. Мешает (только для гостей) → **unauth**.
3. Тип один на единицу — комбинаций `public+auth` не бывает. Смешанная
   страница делится на модули, каждый со своим типом.

## Классификатор-таблица (карточка 2 — правило, а не перечень роутов)

Как пользоваться: ответь на два вопроса из раздела выше
(«нужен ли login?» / «мешает ли login?»), найди столбец,
проверь поведение по строке «гость / пользователь».

| Признак | public | auth | unauth |
| --- | --- | --- | --- |
| Нужен ли login? | Нет | Да | Нет |
| Мешает ли login? (только для гостей) | Нет | Нет | Да |
| Гость: фронт / бэк | видит / `200` | редирект на вход / `401`/`403` | видит / `200` |
| Пользователь: фронт / бэк | видит / `200` | видит / `200` | редирект в приложение / `403` или редирект |
| Смешанная единица | — | делится на модули, каждый типируется отдельно | — |

| Тип | Фронт: страницы\|модули | Бэк: эндпоинты\|модули |
| --- | --- | --- |
| public | лендинг, страница помощи, карточка публичного каталога; общие модули шапки/футера | `GET /health`, `GET /api/catalog`, `GET /api/docs/:id` (публичный документ) |
| auth | дашборд, настройки профиля, модуль оформления заказа внутри смешанной страницы | `GET /api/me`, `POST /api/orders`, `PUT /api/profile` |
| unauth | страница входа, регистрация, восстановление пароля | `POST /api/auth/login`, `POST /api/auth/register`, `POST /api/auth/restore` |

Граничные правила: `health-check` всегда public; `login`/`register`/
`restore` всегда unauth; роли (`admin`/`owner`) — поверх `auth`,
тип от них не меняется. Спорная единица (видна всем, но часть
модулей требует login) — не public целиком, а нарезка на модули
по этой же таблице.
