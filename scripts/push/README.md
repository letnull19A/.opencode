# push — отправка только зафиксированного

Реализация философии пака: **агент не думает про git, а вызывает один
скрипт**; всё детерминированное — в коде.

```
[зафиксированные коммиты текущей ветки]
        │
        ▼
/push → bash .opencode/scripts/push/run.sh → git push
        (только push, без add/commit)
```

Команда `/push` (`.opencode/commands/push.md`) — тонкий runner:
агенту запрещено выполнять любые git-команды самому
(`add`, `commit`, `push`, `--force` и т.д.). Скрипт `run.sh` умеет
только `git push` уже существующих коммитов, поэтому незафиксированные
файлы физически не могут уехать в remote.

## Файлы

- `.opencode/commands/push.md` — команда `/push`, вызывает только `run.sh`.
- `.opencode/scripts/push/run.sh` — детерминированный пуш:
  проверки (git-репозиторий, ветка не detached, remote существует),
  показ `git status --short --branch` + списка коммитов к отправке,
  затем `git push` (или `push --set-upstream` при первой отправке ветки).
- `opencode.json` — `bash .opencode/scripts/push/run.sh*` в allowlist,
  чтобы агент не спрашивал подтверждение на каждый пуш.

## Поведение

- Грязное дерево — предупреждение, а не блокер: скрипт сообщает, что
  незафиксированные изменения остаются локально, и пушит только коммиты.
- Нечего отправлять (`ahead 0`) — успех с сообщением, без пустого push.
- Нет upstream — `push --set-upstream <remote> <branch>` (первая отправка).
- `detached HEAD`, нет remote, упал `git push` — ненулевой exit, агент вставляет
  последние ~15 строк вывода и останавливается, скрипт не чинит.
- Флаги: `--remote <name>` (по умолчанию `origin`), `--dry-run`
  (показать, что уедет, ничего не отправляя). `--force` и аналогов нет
  и не будет — неизвестные аргументы отклоняются.

## Быстрый прогон вручную (без opencode, для проверки скрипта)

```bash
bash .opencode/scripts/push/run.sh --dry-run
bash .opencode/scripts/push/run.sh
```
