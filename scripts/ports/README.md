# ports — кто слушает порты (для devops-агента)

Замена прямому `ss -tulpn | grep`: агент передаёт порты и диапазоны
(`3000-3005,80`), скрипт возвращает pid/процесс/адрес в разбираемом виде. Только чтение.

## Файлы

- `run.sh` — весь пак: позиционный аргумент `3000-3005,80` (порты и
  диапазоны через запятую; без аргумента = все слушающие),
  `--json` (машиночитаемо для агента). Точное совпадение порта (`3000`
  не цепляет `13000`), дедуп строк, сортировка по порту. Пусто = exit 0
  (`no listeners` / `[]`) — свободный порт это ответ, а не ошибка.
  Невалидный токен/диапазон = exit 1 с объяснением.

## Быстрый прогон вручную

```bash
bash .opencode/scripts/ports/run.sh 3000-3005,80
bash .opencode/scripts/ports/run.sh 3000 --json
bash .opencode/scripts/ports/run.sh 65535
```

## Точки адаптации

1. **Права:** devops-агенту разрешён только этот скрипт
   (`bash .opencode/scripts/ports/*`), прямой `ss` у него в `ask`.
2. **Без `ss`:** exit 2 + hint про iproute2. netstat-фолбэка нет
   осознанно — другой формат парсинга, не тащить лишний код.
3. **Чужие процессы:** без прав видны без pid/имени (`-`) — это ограничение
   ядра, а не скрипта; за полным видом — sudo вне зоны агента.
