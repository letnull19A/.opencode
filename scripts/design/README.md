# design — DESIGN.md для фронтенд-агентов

Реализация философии пака: **файл-конвенция в корне проекта, правило —
в `AGENTS.md`, рутина — в скрипте**. LLM думает только о содержимом
(токены/компоненты/решения), всё детерминированное — в коде.

`DESIGN.md` живёт в **корне consumer-репозитория** (рядом с `AGENTS.md`),
а не внутри `.opencode/`. Касается только UI (веб и мобилки).
Владелец файла — **человек**; агентам всех отделов (см. `AGENTS.md` →
Departments) файл — только для чтения, отделу frontend правки строго
запрещены. Нужные изменения агент предлагает точным патчем в чате,
вносит их человек, затем approve → коммит.
Backend/infra-агенты файл игнорируют.

## Файлы

- `template.md` — стандартный скелет (read-only): платформы, стек, токены,
  компоненты, навигация, конвенции, журнал решений, открытые вопросы.
  Меняется только структура, остальной пайплайн не трогаем.
- `init.sh` — создать `DESIGN.md` из шаблона, если его нет
  (`--check` — только проверить, `--force` — перезаписать).
  Смысловые разделы скрипт не заполняет — это работа агента.
- `context.sh` — программный автоинжект: компактный контекст правил
  (стек, токены, компоненты, конвенции, последние 5 решений, свежесть)
  на stdout как готовый блок (`--json` — машиночитаемо). Пустые
  placeholder-строки выкинуты. Нет файла — exit 2 + hint на `init.sh`.
- `guard.sh` — guardrail перед коммитом: сверяет только незакоммиченные
  UI-изменения с `DESIGN.md` как style-guide (error: магический цвет,
  `box-shadow`, глобальный незарегистрированный компонент `shared/ui`/пакет;
  локальное — `app/**/components/*`, page-local, константы UPPER_SNAKE — не
  регистрируется; `design-not-updated` — только при реальных нарушениях
  токенов; warn: магический px — не блокирует).
  Пропускает комментарии, тесты/сториз и строки с `design:ignore`.
  stdout — только JSON, exit 0 чисто / 1 error (коммит только после явного
  approve человека) / 2 нет `DESIGN.md`.
- `README.md` — этот файл.

## Жизненный цикл (правило для агентов, см. `AGENTS.md` → DESIGN.md rule)

1. Перед UI-задачей: `bash .opencode/scripts/design/init.sh --check`,
   если нет — `bash .opencode/scripts/design/init.sh`, затем прочитать
   файл и заполнить пробелы по коду/опросу пользователя. Контекст правил —
   программно через `context.sh` (см. ниже). `DESIGN.md` — style-guide
   (токены/box-shadow/dark/a11y), а не реестр: локальные компоненты нигде
   не регистрируются, глобальные (`shared/ui`, пакет) — переиспользуются.
2. Во время задачи: токены/box-shadow/dark/a11y — только из файла.
   Противоречие с задачей — вопрос пользователю, а не тихий отход от файла.
   Файл агент не правит (read-only) — нужные изменения отдаёт человеку
   точным патчем.
3. После задачи: агент предлагает обновление затронутых разделов + строку
   в журнале решений с датой; вносит владелец, затем approve → коммит.
   На страже — `guard.sh`: без свежих правок при нарушениях коммита нет.

## Быстрый прогон вручную (без opencode, для проверки скрипта)

```bash
bash .opencode/scripts/design/init.sh --check
bash .opencode/scripts/design/init.sh
bash .opencode/scripts/design/init.sh        # no-op: already exists
bash .opencode/scripts/design/init.sh --force # перезапись (сносит правки!)
```
