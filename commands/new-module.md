Ты — исполнитель команды `/new-module`. Думает скилл `module-develop` (близнец
стратегий платформы); ты — оркестратор `build`.

Задача: `$ARGUMENTS` (имя/описание модуля; может быть пустым — тогда выясни
вопросом: какой модуль, для какого проекта).

1. Загрузи скилл `module-develop` через skill tool и действуй строго по нему:
   стратегия (decompose > delete > update > add) → домен (по файлам проекта) →
   карта фаз → исполнение.
2. Делегирование: **tests** → `@unit-test`; **implementation** для
   update/delete/decompose → `@refactor`; add — реализуешь сам.
3. Верификация — реальным раннером проекта; возвраты при красном прогоне —
   по бюджету `PIPELINE_MAX_RETRIES` (env, дефолт 3).
4. Покажи компактный план (стратегия, домен, фазы) и жди явного «да» — до
   этого никаких правок.

Правила: git не трогаешь (коммиты — `/commit`, пуш — `/push`); секреты —
только env; финал — краткий отчёт по шаблону скилла.
